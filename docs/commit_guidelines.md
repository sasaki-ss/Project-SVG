# ■ コミット規約

本ドキュメントは、Project SVG におけるコミットメッセージの記述ルールを定義する。

---

# ■ 目的

* コミット履歴の可読性を向上させる
* 変更内容を「事実ベース」で記録する
* 検索・追跡しやすいログを構築する

---

# ■ 基本フォーマット

```
[type] 対象: 内容
```

---

# ■ type一覧

| type       | 説明                 |
| ---------- | ------------------ |
| [add]      | 新規追加（ファイル・機能）      |
| [update]   | 既存機能の変更（軽微な仕様変更含む） |
| [fix]      | バグ修正               |
| [refactor] | リファクタリング（挙動変更なし）   |
| [remove]   | 削除                 |
| [docs]     | ドキュメントのみ           |
| [test]     | テスト追加・修正           |
| [chore]    | ビルド・設定・雑務          |

---

# ■ 対象（スコープ）

変更対象の層または機能を記述する。

例：

* parser
* model
* render
* loader
* build
* docs

---

# ■ 記述ルール

* typeは必須
* 1コミット1目的とする
* 日本語で記述する
* 主語を書かない（「〜した」禁止）
* 感想・推測を書かない
* 事実のみ記述する
* 抽象的な表現を避ける

---

# ■ OK例

```
[add] parser: XmlNodeExtractor を追加
```

```
[update] parser: 属性抽出ロジックを修正
```

```
[fix] parser: 空属性が無視される不具合を修正
```

```
[refactor] parser: extract処理を関数分割
```

```
[chore] build: CMake設定を更新
```

---

# ■ NG例

```
[add] XMLパーサー作ってみた
```

→ 感想が含まれている

```
[fix] たぶんバグ修正
```

→ 不確定表現

```
[update] いい感じに修正
```

→ 内容が不明確

---

# ■ 補足

* ファイル名変更・移動は [refactor] として扱う
* 依存ライブラリ更新は [chore] として扱う
* 性能改善は [update] として扱う

---

# ■ 一文まとめ

コミットは「変更内容の事実を簡潔に記録するログ」とする。
